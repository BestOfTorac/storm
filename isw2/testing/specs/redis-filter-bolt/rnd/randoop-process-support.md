# RedisFilterBolt Randoop process support

## Trigger for the second support stage

The first frozen Randoop support stage introduced only a concrete
`RedisFilterMapper`.

A generation performed with that frozen mapper support produced 15 regression
tests and successfully made `RedisFilterBolt` constructible.

However, a subsequent semantic audit showed:

- 17 RedisFilterBolt constructor calls;
- 3 calls to `process`;
- 5 calls to `declareOutputFields`;
- 0 normal `process` executions;
- all 3 generated `process` tests expected a NullPointerException.

The exception arose because `collector` was null. The mapper-only stage
therefore solved object construction but did not make normal processing
possible.

No Line/Branch Coverage or PIT result was consulted in making this decision.

## Second-stage decision

A second test-only support component is added:

`RedisFilterBoltRandoopProcessFactory`

It exposes two public factory methods whose declared return type is the
production `RedisFilterBolt` class:

- one accepting a `JedisPoolConfig`;
- one accepting a `JedisClusterConfig`.

The generator continues to choose the configuration and mapper arguments.

Internally the returned object is a small RedisFilterBolt subclass that:

- overrides the protected `getInstance()` testability seam;
- supplies a Mockito `JedisCommandsContainer`;
- installs a Mockito `OutputCollector`;
- never invokes `prepare()`;
- never connects to Redis.

## Why Mockito is used here

Mockito is fixture infrastructure only.

No `when(...).thenReturn(...)` rule is defined for Redis operations.
Therefore the support does not manually choose Redis-present or Redis-absent
test scenarios.

No `verify(...)` call is used.

No assertion or expected result is present in the support.

Mockito merely prevents infrastructure absence from turning every generated
`process()` invocation into the same NullPointerException.

Test sequences and regression oracles remain generated by Randoop.

## Independence

The second support stage contains no information obtained from:

- T_BB cases;
- T_CF cases;
- JaCoCo results;
- PIT results;
- mutation survivors;
- native Apache Storm tests.

The only feedback used was a generator-feasibility observation: every
mapper-only `process()` invocation failed because the infrastructure collector
was absent.

## Frozen generation policy

The final random-generation attempt will use:

- Randoop 4.3.4;
- Java 25;
- seed 20260820;
- target suite size N = 11;
- production RedisFilterBolt;
- frozen mapper support;
- frozen process factory;
- public members only;
- error-revealing tests disabled;
- `prepare()` omitted;
- `cleanup()` omitted;
- no live Redis;
- no manual editing of generated tests;
- no adequacy or mutation feedback during generation.

The process factory is frozen before that generation is observed.
